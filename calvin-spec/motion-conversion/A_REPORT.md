**Method.** Each test feeds the same synthetic `NuvoPoseFrame` stream
through `createMotionValidator(activity)` and through
`createRemoteVerifierRuntime(spec)`. Pose sources: a parametric rig
(`skeleton()` + `armsUp`, `kneeLift`, `heelKick`, `lateralStep`,
`lungePose`, `squatDepth`, `flightTuck`, `repCycleFrames`) plus the app's
own preview keyframes via `demoPoseMapsFor` (arm_raises, deep_squats,
high_knees, jumping_jacks, jump_squats, lunge_jumps, lunges). Every
motion is checked for: clean reps, partial/incomplete reps (must not
count), idle standing, jitter, camera scale 0.6×/1.0×/1.4×, frame
translation, and ±15% torso/leg proportion warps. Transforms are applied
to the whole stream including baseline-seeding idle frames, because a
real framing change affects baseline and motion alike.

**Two semantics to know before reading the table**

1. `sequence_match_v1` is a strict linear phase chain: after a rep
   completes, phase 0 needs a fresh 2-frame dwell to re-arm. All test
   schedules give each action a neutral/standing block of ≥4 frames.
2. `CadenceDetector` (butt_kicks, marching_in_place, lateral_steps)
   spends the first confirmed side establishing a baseline and counts
   `+1` per confirmed *alternation*. The remote counts each complete
   action cycle. On an alternating stream this yields a systematic
   `remote = native + 1` — measured and asserted exactly, not smoothed
   over.

## Honest limitations

- **All equivalence shown here is on synthetic pose streams.** The rig is
  geometrically faithful but cannot reproduce ML Kit landmark noise,
  occlusion, camera framing by real users, or motion blur.
  **Physical-device validation is required before any release is
  promoted** — for every motion in this batch, including the five YESes.
  The draft SQL is staged exactly for that flow (draft status, native
  releases remain the rollback target on every channel).
- **PARTIAL specs are in the repo but must not be promoted for parity.**
  They are useful for device-side exploration; the systematic divergences
  above (cadence +1, same-direction/same-side false positives, the
  jump-flight tuck gate) are real and would change race scores relative
  to the native verifiers.
- **Demo keyframes are not validator-calibrated.** Three preview demos
  (arm_raises, high_knees, jump_squats) feed both engines identical
  streams and diverge in instructive ways (0v0, 2v≤2, 1v0); that is
  evidence about the engines, not about the demos.
- **high_knees jitter uses a stated ±1 tolerance** (remote 3 v native 4
  measured); every other count assertion in the suite is exact.
- **No spec exists for calf_raises.** The gap test proves a raw-threshold
  spec fails at every transform (3v0), and a rigidity check proves no
  instantaneous predicate can see the motion at all.

## Needs an app release first (blocking before the App Store build)

| Motion | Blocking divergence | Capability to ship |
|---|---|---|
| `calf_raises` | No spec possible — motion is a rigid-body delta with zero internal-geometry signature | `baseline_axis_delta` feature kind: point axis minus session EMA baseline, normalized by a reference segment, spec-declared seed/update policy |
| `jump_squats` | Flight gate reads leg tuck, not flight — demo jump counts 1v0 | Same `baseline_axis_delta` primitive for a true airborne predicate |
| `lunge_jumps` | Same-side jump false positive (0v1); can't require the lead leg to switch | (a) normalized signed side-aware delta feature, (b) branching/parallel `sequence_match`, plus the baseline airborne gate |
| `butt_kicks` | Systematic +1 (4v3): remote counts the kick the native spends seeding its baseline | Alternation/cadence semantics: side-latched phase entries, count only after the opposite side confirms (or first-entry suppression) |
| `marching_in_place` | Systematic +1 (4v3) | Same alternation semantics |
| `lateral_steps` | +1 (4v3) **and** same-direction false positives (0v2) | Same alternation semantics — the side-latch must be required, not optional |
| `high_knees` | ±1 jitter loss (3v4) and remote can't score continuous alternation without a full neutral (demo 2v≤2) | Alternation/cadence semantics + a forgiving re-arm/grace policy on the phase chain |

One shared engine upgrade — a side-latching alternation mode on
`sequence_match_v1` — closes three of the seven gaps; the
`baseline_axis_delta` feature closes two more; branching/parallel
tracking plus a normalized side-aware delta closes lunge_jumps.
